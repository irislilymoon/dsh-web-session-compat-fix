# dsh web 会话修复工具（分享版）

用于修复：**旧会话在 desktop 正常，在 web 打开却显示“历史加载失败”**。

适用环境：dsh web `0.2.1-alpha.2` + dsh desktop `0.2.1-rc.2`，两边共用 `%USERPROFILE%\.dsh\sessions`。

> 本分享版不包含任何本机数据：没有备份、没有会话日志、没有会话标题或 ID、没有机器标识、没有本机用户名或路径。

---

## 三个按钮

| 按钮 | 作用 |
| --- | --- |
| `0-检查是否正常.cmd` | 检查补丁是否在位，并扫描全部会话 |
| `1-修复.cmd` | 打补丁（自动备份），修完自动再检查 |
| `2-回滚.cmd` | 还原到最近一次修复前的文件 |

使用顺序：

1. 双击 `0-检查是否正常.cmd`
2. 显示“一切正常”就不用做其它事
3. 显示异常，双击 `1-修复.cmd`
4. 修复后完全退出并重启 dsh web
5. 修复后出问题，双击 `2-回滚.cmd`

---

## 检查会做什么

1. **补丁检查**：确认 3 个 dsh 文件里是否已包含兼容事件类型。
2. **全部会话扫描**：只读检查本机 `%USERPROFILE%\.dsh\sessions` 下所有 v4 会话日志。

结果只有两种：

- `结论：一切正常。`
- `结论：需要修复。请双击 1-修复.cmd。`

如果提示“安装结构不匹配”，或发现 `job/registered`、`job/settled` 以外的未知事件，不要点修复，把窗口内容反馈给提供工具的人。

---

## 为什么会坏

desktop rc2 会往会话里写两个新事件：

- `job/registered`（后台任务注册）
- `job/settled`（后台任务结束）

web alpha2 的旧词汇表不认识它们，读取时直接拒绝，所以显示历史加载失败。补丁只是把这两个类型加入 alpha2 的白名单，会话格式仍然都是 v4，不会改会话内容。

---

## 修复会改什么

只改 dsh 安装目录里的 3 个事件词汇表文件：

- `dsh-session/lib/index.js`
- `dsh-session/lib/types/known-event-types.js`
- `dsh-api-session-controller/lib/client.js`

修复前自动备份到 `backups\backup-<时间戳>\`。

不会修改：

- 任何会话日志
- desktop
- dsh 配置

---

## 注意

- 需要 Windows、Node.js 22.15+，并已安装 dsh web（npm 全局安装）。
- 工具会自动通过 `npm root -g` 找安装目录。
- 如果提示没有权限写文件，右键 `1-修复.cmd` → 以管理员身份运行。
- 如果对方的 dsh web 已经是 rc2 或更新版本，检查会显示一切正常，无需修复。
- 如果提示“安装结构不匹配”，说明版本不同，不要强行修复。
- desktop 和 web 不能同时运行，它们都占用 `127.0.0.1:3080`。
- 第一次修复会自动生成备份；在此之前没有可回滚的备份。
- 检查是只读的；如果 dsh 正在写日志，个别会话可能暂时读取失败，关掉 dsh 再检查即可。
